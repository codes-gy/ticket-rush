# 입장은 앱 안의 고정 주기 스케줄러가 콘서트별 배치로 허용한다 (단일 인스턴스 전제)

입장 허용은 각 앱 인스턴스의 `@Scheduled` 작업(`QueueService.allowNextBatch`)이 3초마다(`queue.allow-interval-ms`) 대기열이 있는 콘서트를 돌며 맨 앞 5명씩(`queue.allow-batch-size`) 처리한다. 전체 콘서트를 매번 훑지 않도록, 대기열이 생긴 콘서트만 `queue:active-concerts` 집합으로 추적한다. 좌석 재고나 결제 처리량과 연동하지 않는 고정 속도 방식이고, 리더 선출이나 분산 락은 없다.

근거: 58005eb, b05430e.

## Consequences

- 알려진 한계: 인스턴스를 N개 띄우면 각자 스케줄러가 돌아 입장 속도가 N배가 된다. `ZPOPMIN`이 스크립트 안에서 원자적이라 같은 회원이 두 번 허용되거나 토큰이 중복 발급되지는 않는다.
- 활성 콘서트가 많아지면 한 주기 안에서 콘서트 수만큼 스크립트를 순서대로 실행한다.
